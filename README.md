# Тула — отражение Огня

Презентация проекта 3D-мэппинга на фасаде Штаба Гвардейского корпуса (Дворцовая площадь, Санкт-Петербург).
Конкурс современного медиаискусства «Страна СВЕТА» 2026, второй тур.

**Автор:** Александр Миндрин · Тула
**Тема конкурса:** «Отражение в искусстве»
**Хронометраж проекта:** 2 мин 30 сек

---

## Структура

```
strana-sveta-2026/
├── index.html            — разметка и весь текст презентации
├── css/styles.css        — стили, включая слайды для PDF
├── js/main.js            — шкала, скраббер, кадры, лайтбокс, появление блоков
├── build-pdf.sh          — пересборка PDF
├── priruchenny-ogon.pdf  — готовый файл, который отдаёт кнопка
├── assets/hero.mp4       — ролик обложки: на фасаде разгорается проекция
├── assets/hero.jpg       — последний кадр ролика: печать и запасной вариант
├── assets/setup-building.mp4 — облёт модели в разделе «Здание», мотается прокруткой
├── assets/setup-frame.webp   — последний кадр облёта: печать и запасной вариант
├── assets/setup.webp      — рабочая модель фасада: заглушка пустых кадров раскадровки
├── assets/bg-tula.webp   — панорама Тулы, фон раздела «Малая родина»
├── assets/map.svg        — контур Тульской области с меткой
└── assets/scenes/        — кадры раскадровки (сюда класть свои файлы)
```

`assets/hero.mp4` — ролик обложки (H.264 без звука, 1,8 МБ, 8,1 с): фасад разгорается, в колоннаде
загорается «Тула». Проигрывается **один раз** и замирает на последнем кадре — атрибута
`loop` нет. Запускается не через `autoplay`, а из `main.js` тем же сигналом, что снимает
паузу с анимаций обложки, — классом `fonts`: иначе ролик отыграл бы, пока кадр ещё прозрачен.
Именно классом, а не событием `animationstart` самого видео: в Safari у анимации,
которая стартует уже в состоянии `paused`, это событие не приходит, и ролик стоял
на первом кадре. Кодирован в Main profile, level 4.0 — старые айфоны отказываются
от более высоких уровней.
`assets/hero.jpg` — тот же последний кадр статикой (72 КБ). Показывается в печати
(видео в PDF не попадает), при системной настройке «уменьшить движение»
и если браузер отказался проигрывать ролик — в режиме энергосбережения Safari блокирует
даже беззвучное видео. В этом случае ролику даётся второй шанс: после первого касания
или нажатия клавиши он запускается и подменяет статичный кадр обратно.
Заменить ролик — положить другой файл под тем же именем и пересобрать из него кадр:
`ffmpeg -sseof -0.1 -i assets/hero.mp4 -frames:v 1 -update 1 last.png`, а из него JPEG: `ffmpeg -i last.png -q:v 6 assets/hero.jpg` (почему именно JPEG — в разделе про сборку PDF).
`assets/setup.webp` — серый clay-рендер фасада (WebP, 66 КБ). Стоит в разделе «Здание» и подставляется
в каждый пустой слот раскадровки, пока туда не положен свой кадр. Заменить любой из них —
просто положить другой файл под тем же именем.

Картинки и видео выводятся в режиме наложения **Screen**: чёрный фон рендера
растворяется в фоне страницы, остаётся только освещённый объём. Если положить кадр
со светлым фоном, он будет выглядеть иначе — режим задан у `.frame img,.frame video`
и у `.hero__stage img` в `styles.css`.

## Что на странице

- **Шкала укрощения** справа — прогресс чтения плюс навигация: у каждого раздела своя
  засечка, при наведении всплывает название, по клику — переход. Градиент шкалы повторяет
  драматургию: уголь → пламя → золото → латунь → филимоновский цвет → зеркало.
- **Скраббер раскадровки** — липкая полоса 2:30 над сценами. Двадцать один сегмент
  пропорциональны длительности, у каждого свой цвет состояния, так что вся драматургия
  читается одной цветной партитурой. Показывает текущий таймкод и название сцены,
  по клику на сегмент — переход к сцене.
- **Фокус чтения** — блок под центром экрана горит в полную силу, остальные гаснут.
  При прокрутке затемнение сильное, в покое смягчается, чтобы не мешать читать.
- **Кадры** открываются во весь экран по клику (когда файл положен в `assets/scenes/`).
  Закрытие — Esc или клик по фону.
- **«Содержание»** идёт сразу за обложкой: на сайте каждая строка — ссылка на раздел,
  в PDF вместо ссылок показаны номера страниц. Номера проставлены руками в разметке
  раздела (`.toc__p`): Chrome не умеет считать страницу цели, поэтому при изменении
  состава слайдов их правят там же — и заодно ожидаемое число страниц в `build-pdf.sh`.
- **Перебивки** — кадр во весь слайд перед разделом или после него. Файл кладут
  в `assets/interludes/` под именем раздела с суффиксом `-open` или `-close`
  (`city-open`, `tex-close`, …; полная таблица — в `assets/interludes/README.md`).
  Пока файла нет, слот не показывается и лишней страницы в PDF не делает. Кадр
  показан как модель на обложке — вписан по центру, края растворяются в чёрном
  (на сайте маской, на слайде градиентом поверх кадра), — класть надо
  горизонтальные кадры 1920×1080 **в JPEG** (почему — в разделе про сборку PDF). Каждая перебивка
  добавляет страницу: после неё правят ожидаемое число страниц в `build-pdf.sh`
  и номера в разделе «Содержание». Сейчас положены три: «Искра»
  (`concept-open.jpg`) перед «Почему Огонь?», «Наковальня» (`cast-open.jpg`)
  перед «Персонажами и образами» и «Ясная Поляна» (`tools-close.jpg`)
  после «Инструментов».
- **Развороты героев** идут галереей под колодой «Персонажей и образов», а в PDF
  занимают по слайду каждый. Клик по карточке в колоде ведёт на разворот — и на сайте,
  и внутри PDF. Кадр кладут в `assets/heroes/shots/<имя>.webp` (или `.jpg`, `.png`),
  имя совпадает с иконкой героя: `iskra`, `ogon`, `bloha`, `levsha`, `molot`, `samovar`,
  `pryanik`, `igrushka`, `garmon`, `tolstoy`. Пока файла нет, в слоте стоит рамка
  с этим именем. Кадр ожидается **на чёрном фоне** — он ложится режимом `screen`,
  так что чёрное растворяется в фоне, а светится только графика; светлой подложки
  в кадре быть не должно, `screen` её выбелит. В PDF Chrome режим наложения
  теряет — кадр ложится непрозрачно, — поэтому фон страницы и слайдов
  разворотов чисто чёрный: чернота кадра совпадает с подложкой, и стык
  не читается в обоих случаях. Кладите кадры **в JPEG**: PNG Chrome
  разворачивает в PDF без потерь, и один такой кадр добавляет к файлу
  почти 2 МБ. Сейчас положены восемь: `iskra`, `ogon`, `bloha`, `levsha`,
  `molot`, `samovar`, `pryanik`, `tolstoy`; ждут своих кадров `igrushka`
  и `garmon`.
- **Раздел «Сетап»** идёт сразу после обложки: базовый рендер фасада без текстур,
  площадка, размер маски и принцип работы со светом — прежде чем говорить о смысле.
- **«Малая родина» собирается по порядку**: сначала прочерчивается контур области
  и в него садится метка, и только потом — по одному — выходят слова с иконками.
  Задержка каждого шага в `--d` у элемента с классом `sq`; слова с иконками стартуют
  на 0,55 с — одновременно с первым штрихом контура, а не после него.
- **Символы и промыслы в «Малой родине» интерактивны**: у каждого термина сводка,
  на мыши она всплывает над словом, с клавиатуры — по фокусу. На тач-экранах наведения
  нет, поэтому там список идёт в столбец по центру, иконки сразу в полный размер,
  а сводки показаны сразу под ними: всплывающая панель не помещалась в ширину,
  а прятать факты за касанием на странице, которую листают, — терять их. В печати сводки раскрыты
  всегда — всплывать в PDF нечему, а факты терять нельзя.
- **Модель в разделе «Здание» мотается прокруткой**: вниз — камера обходит фасад вперёд,
  вверх — назад. Кадр берётся от положения рамки в окне, весь облёт укладывается
  в 200 px прокрутки — константа `SPAN` в `setupScrub()`. Старт привязан к моменту,
  когда рамка целиком вошла в экран.
  Длина задана в абсолютных пикселях, а не долей прохода рамки по экрану, иначе
  на высоком мониторе тот же облёт растягивался бы вдвое. Ролик закодирован all-intra
  (каждый кадр ключевой): при обычном кодировании перемотка назад пересчитывала бы
  группу кадров и дёргалась.
  **Для перемотки серверу нужна поддержка Range-запросов.** GitHub Pages её даёт,
  Live Server тоже; а `python3 -m http.server` — нет, и там ролик замирает на первом
  кадре (`video.seekable` пустой). Это ограничение сервера, а не вёрстки.
- **Раздел «Инструменты»** — короткий список стека без вводного текста и заголовка:
  анимация, композ и звук, по строке на каждую задачу.
- **Раздел «Цвет»** показывает температурную шкалу работы: градиентную полосу от угля
  к зеркалу, семь образцов с кодами и указанием, где каждый цвет звучит, и три правила
  работы с цветом.
- **Финал** построен на этом же фокусе: цитата держит экран одна, выходные данные
  проявляются, когда доходишь до них.
- **Обложка собирается при загрузке**: сначала всплывает здание, следом сверху вниз
  метка, заголовок, факты и подсказка. Анимируются сами элементы, а не обёртки —
  `transform` или `opacity` на `.hero__stage` изолировали бы Screen у модели.
- **Раздел «Малая родина» собирается по шагам**, когда до него дошли: метка раздела,
  линейка слева направо, заголовок, следом контур области **прорисовывается обводкой**,
  в него садится метка геолокации и от неё расходятся волны. Текст выходит параллельно
  с прорисовкой, чтобы не ждать её конца; вся сборка укладывается в 2,4 секунды.
  Контур для этого подставляется в документ инлайном — скриптом из `assets/map.svg`:
  у `<img>` обводку анимировать нельзя. Файл остаётся один, замена карты ничего не ломает.
  Штрих задан в долях длины (`pathLength="1"`), поэтому новый контур любой длины
  нарисуется за то же время.
- **Каждая секция гаснет в чёрное**, когда уходит с экрана. Вуаль создаётся скриптом
  в каждой секции, плотность ведёт переменная `--out`.
  Обложка считается от верхней кромки (она ровно в экран высотой, гасить логично сразу),
  остальные — от нижней: раскадровка втрое выше экрана, и отсчёт сверху зачернил бы её
  прямо во время чтения.
  Сделано вуалью поверх, а не прозрачностью самой секции: `opacity` меньше единицы
  создаёт контекст наложения и отключает Screen у модели.
- **Искры на обложке начинаются со всплеска**: в первый момент их втрое больше, они
  быстрее, краснее и мечутся из стороны в сторону, затем поток остывает до ровного
  подъёма. Жар считается по времени (`heat()` в `main.js`), отсчёт стартует не при
  загрузке, а когда канвас начинает проявляться, — иначе всплеск отгорел бы за кадром.
  На телефоне (до 900 px) искр вдвое меньше и в потоке, и во всплеске: на узком экране
  то же число читается гуще, канвас меньше.
- Искры на обложке, свет под курсором, подсветка карточек, появление блоков при прокрутке.
  Подсказка «Листайте» уходит, как только начали листать.
  Всё это отключается системной настройкой «уменьшить движение».

### Где что правится

| Что | Где |
|-----|-----|
| Название раздела в шкале | атрибут `data-nav` у `<section>` |
| Тайминг сцены | `data-start` и `data-dur` (в секундах) у `.scene` |
| Цвет состояния сцены | `style="--accent:#…"` у `.scene` |
| Палитра целиком | CSS-переменные в начале `styles.css` |
| Температурная шкала | `--coal`, `--flame`, `--ember`, `--gold`, `--brass`, `--crimson`, `--mirror` — одни и те же цвета собирают боковую шкалу, раздел «Цвет» и градиент в разделе «Цвет» |
| Кадр перебивки | файл в `assets/interludes/` — `<раздел>-open` или `<раздел>-close` |
| Номера страниц в «Содержании» | `.toc__p` в разметке раздела `#s-toc` — проставлены вручную, видны только в печати |
| Порядок появления в разделе | `--d` у элементов с классом `sq` в `index.html` — задержка каждого шага |
| Метка на карте области | `.mapfig__pin` в `styles.css` — стоит в центроиде контура, `left`/`top` в процентах; при замене `map.svg` пересчитать |
| Обводка заголовка | псевдоэлемент `.hero h1::after` — текст в `content` дублирует заголовок, при правке h1 менять оба |
| Магма под текстом | класс `magma` в `styles.css` — им залиты заголовок обложки и финальная цитата |
| Глубина затемнения | `--dim` у `:root` (покой) и у `body.scrolling` (прокрутка) |
| Что затемняется | класс `fb` на блоке в `index.html` |

Сумма `data-dur` по всем сценам должна давать 150 секунд — на это опирается скраббер
(константа `TOTAL` в `main.js`).

## Как запустить

В VS Code — через расширение **Live Server**: правый клик по `index.html` → «Open with Live Server».
Сборка не нужна, это чистые HTML/CSS/JS.

Двойной клик по `index.html` тоже работает, но при этом браузер может не подхватить
кадры из `assets/scenes/` — ограничения протокола `file://`. Для работы с раскадровкой лучше Live Server.

## Как вставить свои кадры

Положить файл в `assets/scenes/` и назвать по номеру сцены: `s01`, `s02` … `s21`.
Править код не нужно — при открытии страницы скрипт сам находит файлы и подставляет их в слоты.

```
assets/scenes/s01.jpg   → сцена 01
assets/scenes/s04.mp4   → сцена 04
```

Расширение любое из: `jpg`, `jpeg`, `png`, `webp`, `avif`, `gif`, `mp4`, `webm`, `mov`.

Скрипт сначала читает список файлов в папке одним запросом — так консоль остаётся чистой.
Если листинга нет (так на GitHub Pages), он откатывается на перебор расширений, и в консоли
появятся 404 по ненайденным вариантам. Это нормально: слот просто остаётся с заглушкой.

Из ответа берутся только имена вида `s01.jpg`. Проверка нужна: Pages отдаёт на папку
не листинг, а отрендеренный README, и без фильтра скрипт принял бы эту страницу за список
файлов, не нашёл бы в ней кадров и не ушёл бы на перебор — кадры не подхватились бы вообще.
Файл `.nojekyll` в корне отключает эту обработку.
Видео имеет приоритет над картинкой с тем же именем; картинка при этом становится
постером и уходит в PDF (видео в печать не попадает) — там, где кладёте ролик, кладите и кадр.

Слоты, для которых файла нет, остаются плейсхолдерами. Подпись `alt` подставляется
автоматически из заголовка сцены.

Пропорции слота — 16:9. Кадр вписывается целиком и не обрезается, файл любых пропорций встанет корректно.

Подробности и таблица соответствия сцен — в `assets/scenes/README.md`.

## Экспорт PDF

Кнопка «Скачать PDF» внизу справа отдаёт готовый файл `priruchenny-ogon.pdf` —
без диалога печати, сразу в загрузки.

Файл лежит в репозитории и **пересобирается командой**:

```bash
./build-pdf.sh
```

Скрипт поднимает локальный сервер, прогоняет страницу через headless Chrome и кладёт
`priruchenny-ogon.pdf` в корень. В конце проверяет число страниц: должно быть **38**
(разбивка расписана комментарием в самом скрипте). Если больше — какая-то секция
переросла слайд, надо уплотнить её в блоке `@media print`.

**Пересобирать нужно после каждой правки текста или замены кадров** — иначе на сайте
будет скачиваться старая версия. Если готового PDF нет, кнопка откатывается
на диалог печати, чтобы не вести в 404.

Кнопка скачивает файл через `blob:` — так он гарантированно уходит в загрузки с нужным
именем, а не открывается во вкладке просмотрщика PDF.

**Важно:** по `file://` (двойной клик по `index.html`) скачивание не сработает — браузер
считает каждый локальный файл отдельным источником и игнорирует атрибут `download`,
поэтому PDF просто откроется во вкладке. Нужен Live Server или GitHub Pages.

Формат страницы — 508×285,75 мм, это 1920×1080 px при 96 dpi: 38 тёмных слайдов 16:9.

**Крупные кадры лежат в JPEG, а не в WebP** — из-за того, как Chrome собирает PDF.
WebP он в файл потоком не переносит: распаковывает и кладёт без потерь, и кадр
в 200 КБ разворачивается в слайде в 2,8 МБ. JPEG переносится как есть, и кадр
весит в PDF столько же, сколько файл на диске. Так `hero.jpg` и `tex-building.jpg`
ужали PDF с 8,4 до 4,9 МБ. На вес сайта переход почти не повлиял: при равном
на глаз качестве (`-q:v 6`) JPEG тяжелее WebP на 9 и 18 КБ.

Отдельного печатного дубля у них поэтому нет — один файл и на сайт, и в PDF.
Дубль оправдан там, где печатный кадр действительно другой: так сделан
`setup-frame-print.webp`, у которого растворение краёв запечено в файл.
Но помните, что такой дубль скачивают все посетители сайта, даже спрятанный
`display:none`, — на крупных кадрах это дороже, чем разница между форматами.

Правило простое: **всё, что попадает в PDF крупным растром, кладите в JPEG.**
Мелкие иконки и кадры можно оставлять в WebP — там разница не набирается.

Вручную то же самое: Cmd+P → **Сохранить как PDF**, поля **Нет**,
**фоновая графика включена** (иначе пропадёт чёрный фон), масштаб 100%.

Разбивка раскадровки задаётся обёртками `.pslide` вокруг групп сцен: на экране они
прозрачны и ничего не меняют, в печати каждая — свой слайд со своей шапкой раздела.
Сейчас 21 кадр разложен так: два на первом слайде (там же заголовок раздела), дальше
по три, два последних слайда — по два, чтобы финал не остался в одиночестве.
Перегруппировать = переложить сцены по `.pslide`, но тогда надо поправить и ожидаемое
число страниц в `build-pdf.sh`, и номера страниц в «Содержании».

## Репозиторий и публикация

Код лежит на GitHub: **https://github.com/sashamind/strana-sveta-2026**

```bash
git add -A
git commit -m "что изменилось"
git push
```

Чтобы выложить страницу живой ссылкой, включить GitHub Pages:
**Settings → Pages → Source: Deploy from a branch → main / (root)**.
Или одной командой:

```bash
gh api -X POST repos/sashamind/strana-sveta-2026/pages \
  -f "source[branch]=main" -f "source[path]=/"
```

Сайт появится по адресу `https://sashamind.github.io/strana-sveta-2026/`.
Там же заработает и кнопка «Скачать PDF» — по `file://` она не работает.

## Технические заметки

- Шрифты подключены с Google Fonts: Cormorant (заголовки), Manrope (текст), IBM Plex Mono (служебные подписи и таймкоды)
- Палитра в CSS-переменных в начале `styles.css` — правится в одном месте
- Мобильная вёрстка (до 900 px): двухколоночные сетки схлопываются в одну — включая
  «Здание», модель на обложке не масштабируется за край экрана, строка «Автор · Регион»
  держится в одну строку, карта области уменьшена, финал ужат
- Учтён `prefers-reduced-motion`, есть видимый фокус для клавиатуры, адаптив до 900 px.
  Кадры открываются с клавиатуры (Tab → Enter), лайтбокс закрывается по Esc
- Медиазапрос адаптива обязан быть `@media screen and (max-width:900px)`. Без `screen`
  он срабатывает и при печати: сетки схлопываются в одну колонку, и PDF разъезжается
  с 9 слайдов на 16
- `body` намеренно без `overflow-x:hidden` — иначе ломается `position:sticky` у скраббера
